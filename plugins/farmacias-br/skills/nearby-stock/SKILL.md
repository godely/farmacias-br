---
name: nearby-stock
description: Handle Drogasil medication availability and shopping baskets. Ask about generics for named brands before any lookup, then plan all pickups together.
---

Para “onde eu acho perto de mim?” ou “pode ser em qualquer uma”, consulte as três redes em uma chamada a `plan_purchase`, omitindo `retailer` e `retailers`. Use `retailer` apenas para uma rede escolhida pela pessoa, ou `retailers` para um grupo escolhido. Preserve essa escolha quando a pessoa esclarecer o tamanho da caixa, a dose ou a forma. Consultar um catálogo para esclarecer a apresentação não restringe a busca. Se crossRetailerPlans tiver uma cesta completa, comece dizendo onde pegar cada medicamento. Uma lista vazia em completeRetailers significa que nenhuma rede resolveu tudo sozinha. Para uma única rede parceira, use pickupPlans. Mostre onde retirar cada item, a economia e a diferença de paradas quando houver dois planos. Se a comparação for parcial, diga que são as melhores opções verificadas. Use a ordem das paradas do plano. roundTripKm inclui a volta à origem em linha reta. Quando os planos diferirem, mostre a economia, a diferença de paradas e a diferença de percurso quando disponível. Use os preços dos produtos e a evidência de estoque ou retirada de cada filial. Envie a cesta pelos nomes diretamente ao planejador, inclusive ao revisar uma escolha anterior. Se receber um plano completo, responda usando os pontos de retirada e totais dessa consulta.

Quando a pessoa responder “A de 20. Qual sai mais em conta?”, complete o nome, a dose e a embalagem do mesmo item e consulte as alternativas em uma só chamada. Comece pela caixa de menor preço com estoque ou retirada confirmada para a quantidade pedida. Trate fabricantes como opções para uma compra. Se uma opção tiver estoque, encerre a busca local. Para oferecer 25 km, consulte apenas coverage.canExpand da resposta inteira. Com false ou sem esse campo, responda sobre a disponibilidade local e encerre. Com true, informe a cobertura e aguarde autorização.

Se uma pergunta curta como “Tem paracetamol de 750?” trouxer várias apresentações e o estoque depender da escolha, pergunte apenas pelo detalhe que falta. Por exemplo, se as caixas têm tamanhos diferentes, “Você procura uma caixa com quantos comprimidos?”. Mostre a lista completa quando a pessoa pedir. Use o CEP ou as coordenadas já compartilhadas para esta busca ou peça a localização uma vez, quando ela for necessária.

Accept a supplied SKU silently. Never ask for, mention, or display a SKU, its value, or a barcode in any user-facing reply, including errors and follow-ups. Identify products by name and presentation. Use a numbered list when the person asks to see the products.

These instructions cover Drogasil. When the user names Pague Menos or Drogaria São Paulo, use the retailer workflows in redes-e-precos. Keep every SKU attached to its issuing retailer.

For shopping by commercial name, including “Tem Frontal 2 mg?” and “Quais as opções de Frontal?”, make your first reply a question **before any Drogasil tool call**, including catalog search or SKU lookup: “Quer que eu veja também os genéricos na mesma apresentação? Eles podem custar menos.” For a mixed basket ask once, naming only the brands. “Frontal, Rivotril e loratadina” → “Quer incluir genéricos para Frontal e Rivotril?” “Só para o Rivotril” → Frontal `includeGenerics: false`, Rivotril `includeGenerics: true`, loratadina unchanged. An exact SKU or explicit “com genéricos”, “só a marca” or “só genéricos” settles the preference for that item only. A CEP, quantity or another line with a SKU leaves the named brands open. If location is missing ask for it in the same turn. Reuse the shared origin.

After preferences are settled call `plan_purchase` once with every item, including exact SKUs. The planner resolves product names, obtains branch quantities, and computes both plans. Preserve name, strength, release, pack and quantity. Use `includeGenerics: true` for named brand plus matching generics, false for that brand alone, `genericOnly: true` for generics alone, and `selectedSku` for an exact selection. Preserve option IDs. Keep the available requested brand first, then generics cheapest first. Mention an unavailable named brand above the choices. For a brand-only line with one resolved match and no comparison, give one sentence with name, type, store, distance, reference price and quantity. Do not render a one-row table in that case. If the server returns `needs_generic_preference`, ask the combined question and wait.

“Onde tem mais perto?” means nearest stocked branch per option. Omit `store`. “O que tem na minha loja mais próxima?” pins one physical branch. Pass `store: "nearest"`, show the quantity the Drogasil branch reports, including zero. At Pague Menos or Drogaria São Paulo use fixedStore.branch and pickupAtStore. Say whether the site offered the requested number of packs there. A missing offer leaves shelf quantity unknown. Answer for the selected branch and end the turn. Check other branches only when the shopper asks. If directory coverage is incomplete, qualify nearest by the known distances. If the request itself specifies conflicting releases, clarify first, for example “Você quis dizer Glifage XR ou Glifage de liberação imediata?” Keep unusual strengths such as 507 mg exactly as supplied.

When the top-level `coverage.canExpand` is true for the entire selection, report `coverage.checkedStores` and the distance to the farthest checked branch (`coverage.radiusKm`, if available). Ask “Quer ampliar a busca para até 25 km?” and wait. This question takes precedence over a basket preference prompt. After consent repeat the same tool with the original origin, SKUs, quantities and preferences, adding `expandSearch: true`. A decline ends the search. Offer expansion only when the server returns `canExpand: true`.

For a wider result, show the branches in `expandedSearch.stores` in their returned order, with distance, address and stock. Include the branch phone when supplied. Mark CEP distances as estimates. For a partial result, describe only confirmed availability. Recommend calling before travelling and stop at 25 km.

For lines with choices, render one Markdown table per requested medication in the returned order. Use the returned option IDs and columns **# | Medicamento | Tipo | Farmácia | Distância | Preço de referência | Qtd. em estoque**. Include the returned `type` wherever product options appear. Put unavailable, unknown and failed variants in separate short notes. For ambiguous presentations or rows marked `needsSelection`, describe the differences and let the person choose a numbered option. A lookup failure or unreadable quantity cannot establish zero stock.

For two or more medications, show the returned plans immediately. Show the ordered stops, products and packs at each, estimated total and straight-line round-trip distance. Merge the two headings when `objective` is `both`. Use `tradeoff` for the savings and change in stops and distance. Report any unfilled lines explicitly. Prices are catalog estimates for the participating branches checked. If `searchComplete` is false, label the plans best found and explain the optimum could not be verified. Flag unknown prices, stock or route data when reported.

Finish a basket with one optional question, e.g. “Alguma preferência? Pode responder ‘A2, B1’, ‘só Frontal para A’ ou ‘sem preferência’.” For an option-number reply, resolve each number to its SKU from the displayed table **before** the refresh. Send all original items, quantities and retained preferences in a single fresh `plan_purchase` call, putting that SKU in `selectedSku`. Report a newly unavailable choice. A “sem preferência” reply accepts the plans already shown.

Se a pessoa já escolheu uma apresentação e pergunta “Qual loja tem duas caixas?”, use a seleção anterior, a localização compartilhada e a quantidade pedida em `find_nearby_stock` para a Drogasil. Se ela quer saber especificamente da loja mais próxima, leia nearestStore, inclusive quando a quantidade for zero ou desconhecida. Para opções de produtos, use a tabela de plan_purchase.

“Dá pra pegar hoje?” é uma pergunta sobre quando a pessoa pode ir à loja. Diga qual opção a rede ofereceu. Use o prazo da retirada daquela loja quando disponível. Se ainda não houver prazo, diga isso em uma frase. O aviso de pedido pronto ou a confirmação expressa da loja é que permite dizer que separaram a caixa. Um telefonema serve para perguntar se ainda tem.

For medication facts alone, use only `get_medication_info` once with all names or exact SKUs. No CEP is needed.

For “Tem paracetamol perto de mim?”, use the shared location. If the presentation changes the answer, ask one short question about it. Assume one pack when the person gives no quantity.

Em perguntas sobre concentração, forma ou embalagem, responda aos dados pedidos e cite a ficha. Se perguntarem pelo receituário controlado, cite o campo `prescription.rule` que fundamenta `prescription.form`. Um código da loja não comprova a classificação legal. Quando faltar confirmação, diga “receituário não confirmado”.

Quando a rede parceira devolver quantidade por filial com data de observação, informe a loja, a quantidade e o horário do dado. Uma oferta de retirada vale para o número de caixas pedido. Na ausência de contagem, diga «o site oferece retirada de uma caixa nessa loja» quando essa oferta estiver confirmada.

Na Drogaria São Paulo, indique as filiais confirmadas nos pontos de retirada retornados. Se `pickupVerification.status` for `incomplete`, uma resposta natural é “O site confirmou retirada nestas lojas. Alguns outros pontos ficaram sem identificação.” Se for `directory_failed`, explique que a consulta à lista de filiais falhou. Uma entrega confirmada pode ser informada separadamente. Uma quantidade na prateleira exige evidência de estoque físico da filial.
